## 2 · La pregunta central: ¿ve el detector una CUARTA grafía que se me ocurra a mí?

Escribí seis formas nuevas de llamar a `probeCollide` y las pasé por el candado, una por vez,
restaurando con `md5sum` comprobado. Resultado honesto: **el detector aguanta todo lo que un humano
escribiría, y se le escapa el nombre COMPUESTO.**

| Grafía probada por QA | Fichero saboteado | Candado |
|---|---|---|
| `const { probeCollide } = window.__nefan` (desestructuración) | fixture del propio test | 🔴 lo ve |
| `window.__nefan["probeCollide"](x,z)` (índice con literal) | fixture del propio test | 🔴 lo ve |
| **Un `.mjs` NUEVO sin declarar** (no una reversión de uno existente) | `qa/guiones/999-…mjs` creado a mano | 🔴 `999-…: 1 en el árbol contra 0 declaradas` |
| **`window.__nefan["probe" + "Collide"](x,z)`** | `91:285` | 🟢 **se le escapa** |
| **`` ctx.nefan(`probe${"Collide"}`, x, z) ``** | `118:233` | 🟢 **se le escapa** |
| Un `.ts` en `qa/lib/` que llama a la sonda | `qa/lib/sonda-nueva.ts` | 🟢 se le escapa (límite (a), declarado) |

Y la segunda puerta del mismo seam: **`state().blocked`** también llega a `collidesAt`
(`nefan-hook.ts:237-241`) sin escribir `probeCollide`, así que el candado no la mira. **Medido, hoy no
cuesta nada**: la usa un solo guion (`144:127` y `:160`) y la usa bien — los cuatro rumbos a 0,5 m desde
el jugador, que es su significado. Lo digo porque es el sitio por donde volvería el defecto sin que
nada se entere, no porque haya nada que arreglar hoy.

Los dos intentos de CEGAR el detector (volverlo `match(/__nefan\.probeCollide/g)`; limitarlo a los
ficheros del padrón) salen **rojos en la BASE**, antes de llegar a ningún sabotaje: los guardias de
sujeto (`fuentes.length > 50`, `migrados.length >= 10`) y los cinco unitarios del detector son
verdaderamente portantes. Eso es lo mejor de esta PR y conviene decirlo.

## 5 · Hallazgos

### H1 · IMPORTANTE — el padrón presupuesta NOMBRES, no LLAMADAS (el tercer límite, no declarado)

El detector cuenta cuántas veces se ESCRIBE `probeCollide`. Un alias lo escribe **una vez** y alimenta
**N llamadas**, y el propio test lo dice como decisión de diseño («El alias cuenta UNA vez […] y las
seis llamadas que alimenta van con él»). Consecuencia: en los tres ficheros que aún bindean la sonda
de movimiento —**93, 119 y 133, justo los declarados legítimos**— se pueden añadir consultas de PUNTO
ilimitadas a través del alias y **nada se pone rojo**.

Y esto no es un límite cualquiera: **es la forma exacta del defecto que originó el issue**. El plan lo
escribió él mismo en §2 — «el 81 esconde **6** llamadas tras `pc`» — y el candado nuevo hereda esa
ceguera para los tres ficheros que conservan el alias.

**Reproducción** (desde el árbol limpio en `5d7858c4`):

```bash
cd /home/al/code/ne-fan-qa-p2
python3 - <<'PY'
p="qa/guiones/119-lo-que-el-motor-declaro-al-reanudar-la-partida.mjs"
s=open(p,encoding='utf8').read()
s=s.replace("    return { libre: true, en: 1 };",
  "    const extra = [pc(0,0), pc(1,1), pc(2,2), pc(3,3), pc(4,4), pc(5,5), pc(6,6)];\n"
  "    if (extra.every(Boolean)) return { libre: false, en: 0 };\n"
  "    return { libre: true, en: 1 };", 1)
open(p,'w',encoding='utf8').write(s)
PY
cd nefan-core && npx tsx --test test/la-consulta-de-movimiento-tiene-dueno.test.ts
#   → ℹ pass 10 · ℹ fail 0     (siete consultas de PUNTO nuevas hechas con la sonda de MOVIMIENTO)
cd .. && git checkout -- qa/guiones/119-lo-que-el-motor-declaro-al-reanudar-la-partida.mjs
```

**Qué esperaba el lector del padrón**: que «apariciones: 1» acote lo que ese fichero hace con la sonda
de movimiento. Lo que acota es cuántas veces se teclea su nombre.

**Nota de alcance**: la misma puerta la abre una indirección — un helper en `qa/lib/` que escriba el
nombre una vez y lo reexporte legitima su uso desde todo el banco con UNA entrada del padrón.

### H2 · MENOR — «ninguna cobertura se pierde» es falso, y la frase está commiteada

El bloque 1 del guion 145 afirmaba, **por fichero y por su nombre**, que los cinco migrados SÍ sondean
por punto (`punto > 0`). El candado nuevo solo afirma eso en agregado (`migrados.length >= 10`). Así
que un migrado puede dejar de sondear por punto y salir verde, donde antes salía rojo.

```bash
cd /home/al/code/ne-fan-qa-p2
sed -i 's/probePoint/probePunto/g' qa/guiones/91-la-forja-que-el-motor-pone-ya-no-se-atraviesa.mjs
cd nefan-core && npx tsx --test test/la-consulta-de-movimiento-tiene-dueno.test.ts   # → pass 10 · fail 0
cd .. && git checkout -- qa/guiones/91-la-forja-que-el-motor-pone-ya-no-se-atraviesa.mjs
# lo mismo con el 32, que también estaba en MIGRADOS
```

Con el bloque 1 vivo, ese mismo sabotaje ponía rojo «91 sondea por PUNTO (N llamada(s) a probePoint)».

El coste práctico es bajo —un guion que deja de sondear normalmente deja de medir y sus propios
asertos lo dicen—, pero la **frase** es el problema: `implementacion-662.md` §2 dice «Qué cobertura se
pierde y quién la recoge: **ninguna**», y el docblock COMMITEADO del 145 (`:33`) dice «Lo que el bloque
1 hacía queda cubierto **con creces**». Es la lección de #611 y de
`feedback_justificacion_no_verificada`: la justificación que se escribe después se congela como
documentación falsa. **Basta con decir la verdad medida**: queda cubierto en todo salvo el ancla por
fichero de `probePoint > 0`, que se retira a propósito.
